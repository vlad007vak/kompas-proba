## Подготовка ноутбука (один раз, проверено на ноутбуке Макса)
```text
Ты помогаешь мне подготовить ноутбук (Windows) к хакатону HackNation. Я программирую в команде, у каждого свой Claude Code. Делай всё сам, спрашивай меня только там, где нужно моё участие. Отвечай по-русски.

1. Проверь и выведи версии: git, node, npm, gh, claude.
2. Установи недостающее:
   - Git и GitHub CLI: через winget.
   - Node.js 24 LTS: НЕ через winget (пакет LTS уже ставит Node 26). Скачай официальный MSI node-v24.x-x64.msi с https://nodejs.org/dist/latest-v24.x/, проверь SHA256 по SHASUMS256.txt и установи.
   - Если claude не находится в терминале: добавь %USERPROFILE%\.local\bin в PATH пользователя.
   Программы, запущенные до установки, не видят новый PATH: используй полные пути или скажи мне перезапустить приложение.
3. git config --global user.name / user.email: если пусто, СПРОСИ меня. Поставь init.defaultBranch=main.
4. gh auth status → если не вошёл: gh auth login --hostname github.com --git-protocol https --web (код ввожу я сам).
   Затем: gh auth setup-git (иначе git не берёт данные входа из gh).
5. Узнай мой логин: gh api user --jq .login
6. Отчёт для Влада: логин GitHub, версии, что не получилось.

Правила: ничего не удаляй и не меняй системные настройки без согласия; пароли, токены и коды ввожу только я.
Важно для PowerShell 5.1: польские буквы в git commit -m ломаются — сообщения коммитов передавай через UTF-8 файл (git commit -F файл).
```

## 0. Старт каждой сессии (вставлять первым сообщением)
```text
Ты — Claude Code программиста <ИМЯ> в команде хакатона HackNation. Главный программист — Влад, главный ИИ — Claude Code Влада: он задаёт правила и раздаёт задачи через GitHub Issues.

1. Прочитай CLAUDE.md и docs/WORKFLOW.md полностью и соблюдай их строго.
2. Выполни: git switch main && git pull
3. Покажи мои открытые задачи: gh issue list --label zadanie --label <ИМЯ> --state open
4. Покажи открытые баги в моих папках: gh issue list --label bug --state open
5. Кратко (3–5 пунктов) скажи, что тебе запрещено трогать, и жди, какую задачу я скажу взять.

Отвечай мне по-русски. Тексты в приложении — только по-польски.
```

## 1. Взять задачу
```text
Возьми задачу #<N>.
1. Прочитай её полностью (тело карточки + комментарии): gh issue view <N> --json title,body,labels,comments Если что-то неясно — не угадывай: напиши в задаче комментарий, начиная с "PYTANIE:", и скажи мне, что спросить у Влада. Делай пока то, что от ответа не зависит.
2. Создай ветку <ИМЯ>/<N>-<короткое-описание> от свежего main.
3. Сделай задачу, меняя ТОЛЬКО файлы из раздела "Twoje pliki". Нужна правка в общем файле или в контракте — не делай сам, а напиши в задаче комментарий "ZMIANA WSPÓLNA:" с точным предложением.
4. Коммить маленькими шагами (Conventional Commits).
5. Проверь все "Kryteria akceptacji" из задачи. Запусти приложение (npm run dev) и проверь сценарий руками.
6. Когда всё готово — переходи к промпту "Закончить задачу" сам, без моей команды, но перед merge покажи мне итог.
```

## 2. Закончить задачу
```text
Закончи текущую задачу:
1. git pull --rebase origin main (конфликты в чужих файлах не "чини" — покажи мне).
2. npm run lint и npm run build — должны пройти без ошибок.
3. git push -u origin HEAD
4. Создай PR: описание заполни строго по шаблону .github/pull_request_template.md (это твой отчёт главному ИИ), обязательно "Closes #<N>".
5. Если PR трогает общие файлы/контракт или он большой (новая страница или больше ~300 строк) — добавь метку review-needed и НЕ мёрджи.
   Иначе дождись зелёного CI (gh pr checks --watch) и смёрджи: gh pr merge --squash --delete-branch
6. Дай мне: ссылку на PR, ссылку на Vercel preview (из комментариев PR) и 2–3 строки, что проверить тестировщику.
```

## 3. Исправить замечания ревью
```text
Главный ИИ оставил замечания к моему PR #<N>.
1. Прочитай их: gh pr view <N> --json title,body,comments,reviews
2. Исправь каждое на той же ветке, маленькими коммитами.
3. lint + build, push.
4. Ответь в PR комментарием: что исправлено по каждому пункту.
5. Не мёрджи, если стоит метка review-needed — скажи мне, что готово к повторному ревью.
```

## 4. Исправить баг
```text
Исправь баг #<N>.
1. gh issue view <N> --json title,body,labels,comments — воспроизведи его локально по шагам.
2. Если баг не в моих папках — не трогай, напиши в задаче, чья это зона, и скажи мне.
3. Ветка <ИМЯ>/<N>-fix-<описание>, исправление, lint + build.
4. PR по шаблону с "Fixes #<N>", дальше как в "Закончить задачу".
```

## 5. Если сломался main (CI красный)
```text
CI на main красный. Проверь: gh run list --branch main --limit 3, затем gh run view <id> --log-failed.
Если поломка из-за моего последнего PR — сразу исправь (ветка <ИМЯ>/hotfix-..., PR, merge после зелёного CI).
Если не из-за моего — ничего не мёрджи и скажи мне, чей это PR.
```
